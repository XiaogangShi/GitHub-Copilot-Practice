# 2， 过程中逐步采用到的工具和技术为：
## 层次1， 在 VSCode 中，利用GitHub Copilot 插件来辅助编程。
* 比如 new-code/ 目录，re/ 目录，toGenerateANewDoc-in-GithubCopilot/ 目录

## 层次2，GitHub Copilot  + Genimi 3 Pro
Github Copilot 中发现其默认选取的 LLM 能力不强，实践换用 Claude Sonet, Genemi 3 Pro 等大模型来辅助编程。

## 层次3, LLM 先澄清需求，生成代码，GitHub Copilot 来小修小补
Github Copilot 插件对全新项目的不太方便提供一个 一揽子overview 的概念，不能对用户初始的简单需求进行修改、扩充、消除二义性等，而是力求快速满足用户的需求。所以我在实践中，尝试用 Genimi 3 Pro 来扩展需求。 这是通过 Prompt “打算要求 LLM 用上述需求实现代码。请问描述得足够清晰吗？如果不清晰或者不充分（可能存在二义性），请修改“
* 比如 WebApp/ 目录，Browser-Plugin/ 目录

## 层次4， 使用 Agent 的工作流来固化流程：原始简单需求->  扩展需求 -> 澄清需求 -> 生成架构 -> 生成代码 -> 小修小补
为了提高效率，用 Dify 搭了一个 Agent, 使用 DeepSeek 来 分类问题，扩展需求，澄清需求，生成架构，生成代码。
* 比如 Game/目录, Office/ 目录

### 主要有如下 LLM 的调用，以及一些工作流来筛选关键字做 IF/Else 的流程判断

#### LLM 1
````
你是一个资深的产品经理，也是一个资深的软件开发架构师。你能帮助客户整理思路，提出他真正想要的需求并给出匹配的技术实现方案（比如编程语言，框架，项目目录结构等）
````

````
基于客户原始的简短需求（ {{#sys.query#}}）以及历史沟通的上下文，判断是否能扩展出详细的需求。首先先试着扩展出详细的需求。如果原始的简短需求不清晰或者不充分（比如可能存在二义性），就提出你的具体问题并要求用户一一澄清。

如果需求非常明确，不再需要用户澄清，就输出以下内容：

**总结**：用户的需求澄清完毕

**最终的详细需求** ：XXX (XXX 指代详细需求）

**最终的技术实现方案**： YYY ( YYY 指代 技术方案）

如果需要用户澄清，就再给出这样的提示，“例如，请您澄清所有问题，您可以这样回复：ZZZ"(ZZZ 是基于所有需要澄清内容的，偏向于更普遍的界面、功能选择）

使用 markdown 格式展示。
````
#### LLM 2
````
你是一个资深开发，善于写程序。
````
````

根据详细需求和系统架构设计 （LLM 3 (1)/(x)text) 开发代码。保证代码有足够的中文注释，简洁，可以执行。
````

# 3, 总结
